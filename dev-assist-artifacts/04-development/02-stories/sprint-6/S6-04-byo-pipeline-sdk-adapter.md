## 1. Intent
FR-001 (the UC-01 MUST) promises: *any* PII detector — a user's in-house pipeline, a competitor SDK, a research model — can be scored against the pii-anon benchmark and ranked on the pii-rate-elo leaderboard with **zero harness-core edits**. The callable contract (`Predictor = Callable[[str], Iterable[tuple[str, int, int]]]`), the evaluator (`evaluate_external_system`), the baseline splice (`load_baseline_leaderboard().with_scorecard(...)`), and the CLI (`pii-anon rate-elo --predictor mod:fn`) already exist (S3-era work). What is MISSING is the **SDK half** and the **FR-002 half**: (a) no entry-point discovery — a third-party package cannot *advertise* a predictor and be found (`pip install my-detector` → discovered, zero edits); (b) incumbents (Presidio/GLiNER/Scrubadub/spaCy/Stanza) do NOT go through this path — they are scored only by the frozen `evaluation/competitor_compare.py` (different dataset loader, different matching policy, different signature), so "identical scoring path for incumbents" is unproven. S6-04 ships: the **`BYOPipelineRegistry`** with `pii_anon.byo_pipelines` entry-point discovery (the rating-registry pattern), the **`engine_predictor` bridge** (any `EngineAdapter` becomes a `Predictor`), **five incumbent predictors** (the in-tree `engines/` adapters expressed as ordinary BYO pipelines — incumbents become "BYO pipelines that ship in-tree", identity by construction), **`evaluate_incumbent`** (a single delegation to the literal `evaluate_external_system` — no scoring logic of its own, contract-test-pinned), and **`build_identical_path_leaderboard`** (every system, incumbent or BYO, scored by the same function over the same dataset into one ranked board).

## 2. Approach / scope — the carried DESIGN decisions

### (a) The SDK registry (FR-001 — discovery, zero-edit)
* **`BYOPipelineRegistry`** — mirrors `RatingEngineRegistry` verbatim: thread-safe dict, `register(name, predictor)` (TypeError on non-callable — fail-closed), `unregister`, `get`, `names()` (sorted), `discover_entrypoint_pipelines(group="pii_anon.byo_pipelines")` with the `entry_points().select(group=...)` + `hasattr` fallback and per-EP try/except (NFR-026: enumeration/load failures yield empty/partial, never raise; non-callable loads skipped). A DISTINCT group from `pii_anon.engines`/`pii_anon.rating_engines` so BYO discovery cannot affect detection/rating discovery.
* **Discovery never constructs an engine**: entry-point targets are module-level *functions*; `ep.load()` resolves function objects only. Heavy native deps (GLiNER's model download) can never be pulled by import/discovery.

### (b) The incumbent bridge (FR-002 — identical path by construction)
* **`engine_predictor(engine, *, language="en") -> Predictor`** — wraps `EngineAdapter.detect({"text": text}, {"language": language})` → `(str(f.entity_type), f.span_start, f.span_end)` tuples; drops findings with `None` spans AND **bool spans (the bool-is-int trap — `int(True)==1` would silently coerce)**; engine exceptions PROPAGATE into `evaluate_external_system`'s `on_error` user-code boundary — the exact same error path any BYO predictor hits.
* **Five module-level incumbent predictors** (`presidio_predictor`, `gliner_predictor`, `scrubadub_predictor`, `spacy_ner_predictor`, `stanza_ner_predictor`) — each lazily constructs its `engines/` adapter ONCE (module cache + `Lock`; constructed `enabled=True` since the adapters default `enabled=False`), then delegates through `engine_predictor`. `INCUMBENT_SYSTEMS` tuple + `incumbent_predictor(name)` (unknown → domain-named `ValueError`).
* **`evaluate_incumbent(name, **passthrough) -> ExternalEvaluationResult`** — body is ONE delegation to `evaluate_external_system(incumbent_predictor(name), system_name=name, ...)`. NO scoring logic of its own — a contract test monkeypatches the delegate and pins the single call.
* **`build_identical_path_leaderboard(systems, ...)`** — evaluates EVERY system (incumbent or BYO, indistinguishable `Mapping[str, Predictor]`) via `evaluate_external_system` in sorted-name order → one `BenchmarkScorecard` → `Leaderboard`. The apples-to-apples FR-002 board: same dataset, same strict matching, same composite, same Elo round-robin for every row.

### (c) What is deliberately NOT touched
* `evaluation/competitor_compare.py` — **byte-identical** (md5 `7cae16c89f4c97136e1a12394dae2025`, RISK-6). It remains the legacy artifact producer; the identical path is ADDITIVE alongside it.
* `orchestrator.py` (user-WIP, `0afc6deed62bbd0653ae1051b723bace`) — the pii-anon-itself predictor is `# SWITCH-POINT(ORCH)` Pass-2.
* `competitive_supremacy.py` (`3b842e81c3f03eafd11f9c655c1789a0`) — NOT a control-path change ⇒ **no SDO adversarial close** (re-evaluate if this module ever becomes a control-path-artifact producer/consumer — it does not write artifacts).
* `cli.py` — zero edits needed: `pii-anon rate-elo --predictor pii_anon.eval_framework.byo_pipeline:presidio_predictor` works through the EXISTING CLI (itself a zero-edit proof).
* Never run the benchmark script (it rewrites the user-WIP README + clobbers artifacts).
