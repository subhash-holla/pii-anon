## 1. Intent
The D6 design carried three Security MAJORs as must-do stories; this is **#3: "sandbox the attack harness (ingests adversarial material)"** (`D-implementation-ready-design.md:56`). The DC-09 `attacks/` package runs adversarial code paths — a Tier-3 LLM re-identification adversary (FR-011) and a full-power membership-inference runner (LiRA@128 + Secret-Sharer, FR-013) — driven by **attack specs**. An attack spec describes what an attack does and what it may touch. Because that material is adversarial by definition, the runner that loads and executes specs is a privilege-escalation surface: an attack spec must never be able to (a) trigger **unsafe-deserialization** of an arbitrary object, (b) launch an uncontrolled **subprocess** / **shell-out**, (c) open a **network egress**, or (d) read/write outside an explicit allow-list. This story makes the runner execute every attack under **in-process capability + resource isolation** with a **fail-loud** policy: any spec requesting an out-of-sandbox capability is refused before the attack body runs, and any attack exceeding its CPU/memory/wall-time budget is terminated. The DC-09 `attacks/` package is currently ABSENT (cross-repo line 65: CODE owns `eval_framework/attacks/`); this story creates it with the isolation substrate as its foundation, so every real attack body landed later runs sandboxed by construction.

## 2. Approach / scope
- **Package home (new):** create `src/pii_anon/eval_framework/attacks/` — the DC-09 home the design assigns to CODE (`D-implementation-ready-design.md:65`, "CODE owns … `eval_framework/attacks/`"). It does NOT exist today (verified). This story seeds it with `__init__.py` + `sandbox.py` + `spec.py` only; the attack bodies are successor stories.
- **`spec.py` — the safe structured loader (no unsafe-deserialization).** `AttackSpec` is a frozen dataclass with explicit typed fields: `attack_id: str`, `attack_kind: Literal["reid","mia","reconstruction"]`, `runner: str` (a dotted name resolved ONLY against an in-code **allow-list registry** of known attack callables — never a free `importlib`/arbitrary-object resolution), `params: Mapping[str, str | int | float | bool]` (scalars only), `budget: ResourceBudget`, `allowed_paths: frozenset[str]`, `network: Literal["deny"]` (the only legal value — there is no allow option in v1). `load_attack_spec(source: str | Mapping) -> AttackSpec` parses ONLY a safe structured form (a JSON document or an already-parsed mapping) via the stdlib structured parser; it NEVER uses an arbitrary-object deserializer and NEVER constructs objects named in the data. The loader **rejects loudly** (`SandboxViolation`) any spec that: carries a `runner` not in the allow-list registry; carries a `params` value that is not a JSON scalar (no nested objects that could smuggle a callable); sets `network` to anything other than `"deny"`; or names a path outside `allowed_paths`.
- **`sandbox.py` — the execution guards.**
  - `ResourceBudget(cpu_seconds: float, address_space_bytes: int, wall_seconds: float)` — a frozen dataclass with validated positive bounds and project-pinned defaults (`DEFAULT_CPU_SECONDS`, `DEFAULT_AS_BYTES`, `DEFAULT_WALL_SECONDS`).
  - `SandboxPolicy` — captures the allow-list (`allowed_paths`), the network posture (egress denied), and the budget. Exposes `assert_path_allowed(path)`, `assert_no_network()`, `assert_no_unsafe_capability(spec)`.
  - `AttackSandbox.run(spec, attack_callable, *, inputs)` — the single execution chokepoint:
    1. **Capability pre-check (fail-loud):** validates the spec against the policy (runner in allow-list; `network=="deny"`; every declared path ⊆ `allowed_paths`; no scalar-only violation). Any failure raises `SandboxViolation` **before** the attack body is invoked.
    2. **Resource limits (in-process, AGENT_SIMULATED real where the platform allows):** where `resource` is importable (POSIX; verified present on this dev host), apply `resource.setrlimit(RLIMIT_AS, ...)` and `RLIMIT_CPU` (soft) inside the execution context, restoring prior limits afterward; a `wall_seconds` watchdog (a stdlib timer/thread-based deadline, NOT a subprocess) terminates an over-budget attack and raises a `SandboxBudgetExceeded` (subclass of `SandboxViolation`). On platforms where a given rlimit is unavailable, the in-process guard **degrades to the watchdog + a recorded `platform_limit_unavailable` audit note** (never silently no-ops; fail-loud-or-record).
    3. **Network-egress refusal:** the sandbox installs an in-process egress guard for the duration of the run (a socket-connect interceptor that raises `SandboxViolation` on any outbound connect attempt) and asserts `network=="deny"`. Real kernel-level egress blocking (namespaces) is Pass-2.
    4. **No subprocess / shell-out from a spec:** the allow-list registry resolution is the ONLY way a spec selects code; there is no spec field that names an external program, and the loader rejects any attempt to smuggle one. A `[SECURITY-TEST]` asserts the attacks package source contains NO unsafe-deserialization call, NO subprocess/shell-out call, and NO arbitrary dynamic-eval call (AST/source scan, ZERO matches).
  - `run_attack_under_sandbox(spec_source, *, inputs, registry=DEFAULT_ATTACK_REGISTRY) -> AttackResult` — the public convenience entry: load → resolve runner from the allow-list → `AttackSandbox.run`. Returns a structured `AttackResult` (`attack_id`, `outcome`, `terminated_for_budget: bool`, `audit: list[str]`).
- **Wrap, don't rewrite.** The legacy `harness/attack.py` `reconstruction_attack_score` and `harness/stream_synth.py` stay **byte-identical**. The sandbox registers `reconstruction_attack_score` as one allow-listed runner (a synthetic, side-effect-free attack) so there is a concrete end-to-end "well-formed attack runs to completion within budget" path in-tree without any new attack body.
- **Boundary + isolation hygiene.** `eval_framework/attacks/` may import stdlib + `eval_framework` siblings it needs, but imports nothing from `swarm`/`moe`/`fusion`/`policy` (mirrors the DC-06/DC-07 import-boundary discipline; a boundary test pins it). Determinism (AX-002): the guards are deterministic given a spec; no wall-clock value leaks into an `AttackResult` field that is asserted for equality.

## 3. Given / When / Then (acceptance — concrete, testable)
- **A1 — unsafe-deserialization is refused (the headline security gate). `[SECURITY-TEST]` `[UNIT-TEST]`** **Given** an attack spec whose `params` (or any nested field) attempts to smuggle a non-scalar / object-construction payload (e.g. a mapping shaped to trigger arbitrary-object reconstruction), **when** `load_attack_spec` runs, **then** it raises `SandboxViolation` naming the offending field, and NO object named in the data is ever constructed. **Property test** (`@given` over generated malformed specs): every spec carrying a non-scalar `params` value is rejected; ZERO reach the runner.
- **A2 — a subprocess / shell-out request is refused. `[SECURITY-TEST]` `[UNIT-TEST]`** **Given** an attack spec whose `runner` is a dotted name NOT in the allow-list registry (the only channel by which a spec could try to reach an external program / shell-out), **when** `run_attack_under_sandbox` runs, **then** it raises `SandboxViolation` (runner-not-allow-listed) before any execution. **AST/source guard:** `test_attacks_package_has_no_unsafe_execution_call_signatures` asserts the `attacks/` source contains zero unsafe-deserialization calls, zero subprocess/shell-out calls, and zero arbitrary dynamic-eval calls.
- **A3 — network egress is refused. `[SECURITY-TEST]`** **Given** a well-formed spec and a synthetic attack callable that attempts an outbound socket connect, **when** it runs under `AttackSandbox`, **then** the egress guard raises `SandboxViolation` (network-egress-denied) and the attack does not complete; **and** any spec with `network != "deny"` is rejected at load time.
- **A4 — an over-budget attack is terminated. `[SECURITY-TEST]` `[UNIT-TEST]`** **Given** a spec with a small `ResourceBudget` (`wall_seconds` tight, and `address_space_bytes`/`cpu_seconds` where the platform supports the rlimit) and a synthetic attack that exceeds it (busy-spin past `wall_seconds`, or allocate past the AS limit), **when** it runs under the sandbox, **then** it is terminated and `SandboxBudgetExceeded` is raised with `terminated_for_budget=True`; on a platform lacking a given rlimit, the wall-clock watchdog still terminates it and an `platform_limit_unavailable` audit note is recorded.
- **A5 — a well-formed attack runs to completion within budget. `[CONTRACT-TEST]` `[INTEGRATION-TEST]`** **Given** the allow-listed synthetic `reconstruction_attack_score` runner, a generous budget, `network="deny"`, and `allowed_paths` covering only what it touches (nothing — it is pure over in-memory synthetic strings), **when** `run_attack_under_sandbox` runs it on synthetic masked-text inputs, **then** it returns an `AttackResult` with the expected reconstruction outcome, `terminated_for_budget=False`, ZERO `SandboxViolation`, and an audit trail recording the capability checks that passed.
- **A6 — path allow-list is enforced. `[SECURITY-TEST]`** **Given** a spec whose `allowed_paths` is empty but whose attack attempts to open a path, **when** the attack calls `policy.assert_path_allowed(path)` (the sanctioned access shim), **then** it raises `SandboxViolation` (path-not-allow-listed); a spec declaring a path outside its `allowed_paths` is rejected at load time.
- **A7 — synthetic-only, least-privilege (AX-001 / AX-006). `[AUDIT]`** **Given** the full test module, **then** every fixture spec + every input is SYNTHETIC (no real PII, no real key, no real network target); an audit assertion confirms no `AttackResult.audit` line and no fixture embeds a real-PII-shaped or real-secret-shaped value, and the sandbox grants only the capabilities the spec explicitly declares (default-deny: empty `allowed_paths`, `network="deny"`).
- **A8 — import-boundary + determinism. `[PROPERTY-TEST]`** **Given** an AST scan of the 3 new `attacks/` source files, **then** none imports from `swarm`/`moe`/`fusion`/`policy`; **and** two runs of `run_attack_under_sandbox` on the same spec + inputs yield equal `AttackResult` (excluding any explicitly non-deterministic timing field, which is not part of equality).
