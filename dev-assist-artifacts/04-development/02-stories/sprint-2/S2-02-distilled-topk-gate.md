## 1. Intent
S2-01 built the empty socket; S2-02 builds the plug + the thing that manufactures it. The **runtime** `DistilledTopKGate` is the learned gate that re-weights experts per (entity_type) from a verified artifact — and because `gate_v1.json` is a **control-path** artifact (an attacker who can write it biases the detector — exactly why S2-05 exists), the gate MUST be constructed ONLY from a payload that passed the S2-05 fail-closed `verify_on_load=True` boundary (the S2-01 gate's explicit S2-02 entry-gate obligation). The **offline** trainer distills the frozen XGBoost survival oracle into that compact artifact (RRS-up-weighted, oracle-hashed, feature-versioned) and signs it via S2-05's `KeyRing`. The gate is **advisory**: it can re-weight/re-order experts but can never drop a shared-layer span (S2-01's `FloorProjectingFusion` re-injects post-fusion — re-confirmed by an integration test). Absent or unverifiable → the static `entity_strengths` softmax (NFR-026). Everything runs for real in-tree against synthetic oracles + a real tiny `importorskip`-gated XGBoost oracle; a gate distilled on real Tier-3 survival labels + real key custody are Pass-2.

## 2. Approach / scope
- **`routing/distilled_gate.py` — the runtime gate (control-path, security-critical).**
  - `DistilledGatePayload` (frozen) — validated view over the verified payload dict: `gate_feature_version: int`, `oracle_hash: str`, `schema_version: int`, `temperature: float`, `weights: Mapping[entity_type, Mapping[expert_id, float]]`. A `from_payload(dict) -> DistilledGatePayload` validator rejects a malformed/partial payload **loud** (`GatePayloadError`) — non-finite/negative weights, missing required keys, wrong `schema_version`. (The SIGNATURE is already checked by `load_verified_gate`; this validates the SHAPE of the verified content.)
  - `DistilledTopKGate` implements the S2-01 `RoutingGate` Protocol: `adjust(entity_type, context, base) -> list[tuple[str,float]]`. Looks up `weights[entity_type]`; for each `(expert_id, base_weight)` in `base`, multiplies by the gate's advisory factor for that expert (or 1.0 if the gate has no opinion), then the router's existing `_normalize_weights` re-normalizes (so `adjust` returns a raw advisory vector the router validates — never emits NaN/negative). **Unknown entity_type / empty gate opinion ⇒ return `base` unchanged.** `top_k`-aware: the gate may re-order so a different top-k is selected, but it can only RE-WEIGHT experts already in `base` (it never invents an expert and never zeroes the floor — the floor is downstream).
  - `load_distilled_gate(path, *, key_ring) -> DistilledTopKGate | None` — a thin wrapper that calls `moe.load_verified_gate(path, key_ring=key_ring, verify_on_load=True)` (**the ONLY construction path** — no `verify_on_load=False` escape, no raw-dict constructor on the production seam) and returns a `DistilledTopKGate(DistilledGatePayload.from_payload(verified))`, or `None` when the artifact is absent (⇒ caller keeps the static softmax, NFR-026). A present-but-unverifiable artifact raises `GateSignatureError` (fail-closed, S2-05) — never a silent static fallback.
- **`routing/gate_distillation.py` — the offline producer (NOT on the hot path).**
  - `SurvivalOracle` Protocol: `predict(features: list[list[float]]) -> list[float]` (the existing `XGBoostMetaLearner` satisfies it structurally; a deterministic synthetic oracle is used for the pure-determinism teeth). The oracle is the **survival teacher** (P(span is a true positive)).
  - `distill_topk_gate(oracle, records, *, temperature=1.0, seed=42, feature_version=1) -> dict` — groups training records by `(entity_type, expert_id)`; computes each group's **RRS-up-weighted oracle-survival mean** (the teacher's soft survival, weighted by `compute_sample_weights_from_records` so Tier-3 hard cases sharpen the gate) — this per-cell mean is the **closed-form BCE/KL-optimal compact student** (for a table-shaped student, the BCE- and KL-minimizing per-cell constant is exactly the weighted mean of the teacher's soft targets; documented, not gradient-fit — a gradient student is an unnecessary, less-deterministic equivalent); then within each entity_type applies a **temperature-softmax** across experts to yield the advisory routing `weights[entity_type][expert_id]` (Switch/Mistral-style). Stamps `oracle_hash` (sha256 of the oracle's stable bytes — `oracle.model_bytes()` or `repr`-of-the-synthetic), `gate_feature_version`, `schema_version`, `temperature`. **Deterministic**: same `(oracle, records, temperature, seed)` ⇒ byte-identical `canonical_gate_bytes(payload)` (NFR-005). (`select_f2_threshold` is reused to record the gate's recommended emission threshold in the payload metadata — advisory, not a hard cut.)
  - `emit_signed_gate(payload, *, key_ring, path) -> None` — wraps `payload` via `key_ring.sign_payload(payload)` (S2-05) and writes the `{payload,signature}` envelope JSON to `path`. The round-trip `emit_signed_gate(...)` → `load_distilled_gate(path, key_ring)` is the integration spine.
- **Optional wiring (`"distilled_moe"` v2 mode).** Register via `register_fusion_strategy_v2` a factory that, given a `FusionBuildSpec` carrying `gate_path`/`key_ring`, builds `MoEFusionStrategy` whose inner `MoERouter` is given `gate=load_distilled_gate(spec.gate_path, key_ring=spec.key_ring)` (or no gate when `gate_path is None`). This is the wired control-path. **Do NOT change `build_fusion`'s public signature** to source `gate_path` — if threading it cleanly needs that, keep the wiring behind the v2 registry + a factory closure and DEFER the public-signature thread to a follow-up (note it). The recall-floor wrap (`FloorProjectingFusion`) stays.
