## 1. Intent
S2-01 widened the selection logits; this story makes them **latency-aware** under an SLA. The technique is DeepSeek-V3 **loss-free load balancing**: instead of an auxiliary load-balancing loss, add a per-expert **bias** to the selection logits so cheaper experts float up the selection ranking. The bias is computed from a per-expert latency cost carried in `ExpertSpec.metadata["latency_cost_ms"]` (operator-supplied; optional). It nudges the *selection set* + the softmax mass toward cheaper experts when an SLA is active — and is **completely inert by default**. It is **advisory and selection-only**: it never mutates `EnsembleFinding.confidence`, never alters `Shared`-layer membership, and is structurally downstream-blind to the recall-floor (`FloorProjectingFusion` re-injects shared spans post-fusion — re-confirmed by an integration-style test). Everything runs for real in-tree against synthetic registries; tuning β toward the LOCKED 1522/753/200 per-hardware latency budgets + committing the numeric ceilings is S7-04 + Pass-2.

## 2. Approach / scope
- **`SLABias` (frozen dataclass) — the SLA config.** `SLABias(strength: float = 0.0, reference_ms: float = 1.0)`. `strength` is β ≥ 0 (the bias magnitude); `reference_ms` is a logit-scale normalizer (so the penalty is unit-decoupled). Frozen + hashable (mirrors S2-01's `RouteContext`). `strength == 0.0` ⇒ the bias term is identically 0 ⇒ fully inert. Kept **distinct from `RouteContext`** (the gate's feature channel) to avoid conflation — the SLA is router-construction state, not a per-call gate feature.
- **`LATENCY_COST_KEY = "latency_cost_ms"` + `_latency_cost(spec) -> float | None`.** Reads `spec.metadata.get("latency_cost_ms")`; returns the value only when it is a real, finite, non-negative, non-`bool` number; else `None` (no opinion — never penalized, never raises). A non-finite / negative / bool / non-numeric cost is coerced to "no cost" (bias 0) — the bias never produces a NaN/negative logit.
- **`MoERouter.__init__(..., sla_bias: SLABias | None = None)` (keyword-only, default `None` = inert).** Stores `self._sla_bias`; adds a lazily-built `self._latency_cost_cache: dict[str, float] | None` populated by `_latency_cost_by_id()` (`{expert_id: cost}` over `available_experts()`), invalidated by `clear_cache()`.
- **The bias step in `route()` (the only behavioural change).** After building `scores: list[(expert_id, strength)]` and the `if not scores: return []` guard, and **before the sort**, when `self._sla_bias is not None and self._sla_bias.strength != 0.0`:
  `biased_logit(e) = strength_e − β · (cost_e / reference_ms)` for each expert that carries a latency cost (others keep their raw logit). Then sort with a **total-order tie-break**: `scores.sort(key=lambda x: (x[1], x[0]), reverse=True)` (was `key=lambda x: x[1]`). The performance-floor swap, the softmax, the advisory gate `adjust()`, and `_normalize_weights` are **unchanged** — the bias only reshapes `scores` (selection logits), affecting both top-k membership and the softmax weights, and the router's existing validators remain the final guard.
- **Optional wiring (additive, all defaulting `None`).** Thread `sla_bias=None` through `MoEFusionStrategy.__init__` → inner `MoERouter`, and add `sla_bias: SLABias | None = None` to `FusionBuildSpec`, carried in `build_fusion` exactly as `gate_path` is (the spec carries it; **`build_fusion`'s public signature is UNCHANGED**). The recall-floor wrap (`FloorProjectingFusion`) stays.

## 2a. Pre-claim de-risk (verified against live code 2026-06-03)
- **RISK-1 — THE POWER-TIER TRAP (orthogonality is load-bearing):** the bias reads **ONLY** `ExpertSpec.metadata["latency_cost_ms"]`. It must **never** read or modify `default_weight` (the NFR-004 power/reliability signal — `route()` does not read it today) and **never** `entity_strengths`. The latency signal is a *new third signal*, orthogonal to the power tiers. S2-04 traces **NFR-009/010** (latency/throughput), NOT NFR-004. **A9 pins this**: mutating an expert's `default_weight` changes nothing under the bias; mutating its `latency_cost_ms` does.
- **RISK-2 — advisory / selection-only (AX-003 + confidence immutability):** the literal DC-03 acceptance criterion is "bias changes the selection set but NOT `EnsembleFinding.confidence` and NOT `Shared` membership." The bias lives entirely in `route()`'s `scores`, structurally upstream of and decoupled from `MoEFusionStrategy.merge`'s confidence math, the `SharedLayerProjector`, and the `regex-oss` shared subset. **A3/A4/A5 pin** byte-identical confidence (single-expert-cluster isolation), byte-identical floored output under an aggressive β, and identical shared membership.
- **RISK-3 — determinism (NFR-005 / AX-002):** no `random`/`uuid`/`time`/`secrets`. Equal biased logits resolve by the `(logit, expert_id)` secondary key → total order, stable across registry-insertion permutation. **A6 pins** replay-equality + permutation-invariance.
- **RISK-4 — graceful default-off (NFR-026):** `sla_bias=None`/`strength=0.0` ⇒ the bias branch is not taken ⇒ `route()`/`route_all()` are byte-identical to the S2-01 static-softmax baseline; 0 unhandled exceptions; an expert with no `latency_cost_ms` is never penalized. **A7/A8 pin** this.
- **RISK-5 — no new dependency / pure-stdlib:** scalar `math` only (no numpy) — so the `npt.NDArray` strict-mypy gotcha does not arise. `SLABias`/`_latency_cost` live in `moe.py` (top of the dependency order; `fusion`/`routing` import *from* `moe`). No new import edge; `routing/*` imports nothing from `eval_framework.rating`/`attacks`/the SDO gate.
- **RISK-6 — user-WIP / off-limits:** `orchestrator.py` + `tests/test_moe_enhancements.py` NOT touched (byte-identical md5); `evaluation/competitor_compare.py` byte-identical (RISK-6, md5 `7cae16c89f4c97136e1a12394dae2025`); `artifacts/benchmarks/*` never written; `routing/floor_fusion.py`/`shared_layer.py` byte-identical. **AX-001**: all registries/experts synthetic.

## 3. Given / When / Then (acceptance — concrete, testable)
- **A1 — SLA bias shifts selection toward the cheaper expert (NFR-009) `[UNIT-TEST]`.** **Given** two experts over one entity type with inverted strength/latency (`expert-fast` strength 0.60 / `latency_cost_ms` 1.0; `expert-slow` strength 0.65 / `latency_cost_ms` 50.0), **when** `route()` runs with `SLABias(strength=β>0)`, **then** `dict(out)["expert-fast"]` strictly **increases** vs the `strength=0` baseline (the bias lifts the cheaper expert's selection mass).
- **A2 — bias changes top-k membership under truncation (NFR-010) `[UNIT-TEST]`.** **Given** a registry with > `top_k` experts where a cheap expert sits just below the top-k strength cutoff, **when** a large-enough β is applied, **then** the cheap expert is promoted **into** the selected set (and a costly one demoted) — proving the bias changes the *selection set*, not only weights.
- **A3 — `EnsembleFinding.confidence` byte-identical (DC-03) `[UNIT-TEST]`.** **Given** a single-expert-per-type cluster (so weights don't move the average), **when** the full `MoEFusionStrategy.merge` runs with vs without `sla_bias`, **then** every `EnsembleFinding.confidence` is byte-identical; **and** no `confidence` field of any `EngineFinding`/`EnsembleFinding` is written by the bias path (the bias changes only which experts/weights, never a stored confidence).
- **A4 — recall-floor byte-identical under aggressive bias (AX-003) `[UNIT-TEST]` `[AUDIT]`.** **Given** an aggressive `SLABias` that would deprioritize `regex-oss` in routing, **when** the REAL `FloorProjectingFusion(MoEFusionStrategy(... sla_bias ...))` merges a checksum-gated shared span, **then** the floored span set (`provenance=shared_floor` re-injections + survivors, by type-carrying key) is **byte-identical** to the `sla_bias=None` run.
- **A5 — `Shared` membership invariant (AX-003) `[UNIT-TEST]`.** **Given** the same aggressive bias, **when** the shared subset fed to the projector is computed bias-on vs bias-off, **then** the `regex-oss` shared input set + the re-injected keys are identical (membership invariance, distinct from A4's output invariance).
- **A6 — determinism + total-order tie-break (NFR-005 / AX-002) `[PROPERTY-TEST]`.** **Given** the same `SLABias`, **when** `route()`/`route_all()` run twice (and across a registry-insertion-order permutation crafted to produce equal biased logits), **then** the outputs are equal and the order is stable (the `(logit, expert_id)` secondary key makes the sort total).
- **A7 — default-off byte-identical to static softmax (NFR-026) `[UNIT-TEST]` `[PROPERTY-TEST]`.** **Given** `sla_bias=None` (and separately `SLABias(strength=0.0)`), **when** `route()` runs over the representative entity set on the default registry, **then** it equals the independent static-softmax oracle (reuse the S2-01 `_independent_static_softmax` helper) — zero behaviour change by default.
- **A8 — missing-metadata expert not penalized `[UNIT-TEST]`.** **Given** an expert with **no** `latency_cost_ms`, **when** any β is applied, **then** its biased logit equals its raw strength (bias 0); only experts carrying the key are biased; a `latency_cost_ms` of `NaN`/`+inf`/negative/`True`/non-numeric is treated as "no cost" (ignored, never raising).
- **A9 — `default_weight` orthogonality (THE POWER-TIER TRAP) `[UNIT-TEST]` `[AUDIT]`.** **Given** the bias active, **when** an expert's `default_weight` is mutated between two routes, **then** nothing changes; **when** its `latency_cost_ms` is mutated, the routing shifts. Pins that the bias reads `metadata["latency_cost_ms"]` and **never** `default_weight` (NFR-004 power) nor `entity_strengths`.
- **A10 — existing callers intact `[UNIT-TEST]`.** **Given** `sla_bias` set, **when** `route_all()` and `MoEFusionStrategy.merge` run, **then** they still produce valid Σ=1.0 distributions / valid `0 ≤ confidence ≤ 1` findings; **and** with `sla_bias=None` they match the recorded S2-01 reference (no regression on the two bare call sites).
- **A11 — `SLABias` frozen + hashable `[UNIT-TEST]`.** **Given** an `SLABias`, **then** it is immutable (mutation raises `FrozenInstanceError`) and hashable (usable as a dict key / in a set), mirroring `RouteContext`.

## 5. Notes / non-goals
- **Non-goal:** the committed numeric latency ceilings (p50/p95/p99 per power class) — those are **S7-04** (NFR-009). S2-04 ships only the *mechanism* (the selection bias) + its invariants.
- **Non-goal:** per-key-epoch closed-loop tuning of β against observed-vs-budget latency on real hardware — **Pass-2** (the in-tree teeth pin the static per-expert bias + the invariants; real-hardware calibration toward the 1522/753/200 budgets is the user's Pass-2).
- **Non-goal:** any change to `EnsembleFinding.confidence`, the `Shared`-layer membership, or the recall-floor (`FloorProjectingFusion`/`shared_layer` byte-identical) — the bias is advisory and selection-only.
- **Non-goal:** changing `build_fusion`'s public signature (carry `sla_bias=None` in the spec, exactly as `gate_path` is carried).
- **Non-goal:** numpy / a vectorized bias — scalar `math` is correct + simpler and keeps `mypy --strict` trivially clean.
