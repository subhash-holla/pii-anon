## 1. Intent
`gate_v1.json` is a **control-path** artifact: when present, the DistilledTopKGate (DC-02) steers which experts are weighted/early-exited for each entity type. The design SME flagged this as a **privilege-escalation risk** — an auto-discovered file on disk that silently re-weights the detector is a tampering surface (an attacker who can drop or edit the file can bias routing, e.g. suppress an expert for a target entity type). The advisory-only constraint (it can never drop a Shared span — the S1 recall-floor still wraps everything) bounds the blast radius but does **not** eliminate it: a poisoned gate can still degrade recall on UNCERTAIN chunks and skew the SLA/early-exit behaviour.

This story makes the gate **unforgeable and fail-closed**: produce a **detached signature** over the *canonical serialization* of the gate envelope, and **verify it on every load**. Verification **FAILS LOUD** (raises `GateSignatureError`) on (a) a tampered byte, (b) a missing/empty signature, (c) an unknown or retired key id, or (d) a malformed envelope — it **never silently accepts** and **never silently falls back** to the unsigned content. The legitimate "no gate present" path stays the documented NFR-026 graceful degradation (static `entity_strengths` softmax) — *absence* of the artifact is fine; an artifact that *is present but fails verification* is a hard error, not a fallback.

## 2. Approach / scope
- **Canonical serialization (the signed bytes).** `canonical_gate_bytes(payload: dict) -> bytes` = UTF-8 of `json.dumps(payload, sort_keys=True, separators=(",", ":"), ensure_ascii=False)` over the **payload only** (everything except the signature envelope). Deterministic, byte-identical across replays (NFR-005/AX-002) so the signature is stable. The signature is computed over these exact bytes — verification recomputes them, so any field reordering/whitespace change is irrelevant and any *value* change is caught.
- **Detached-signature envelope.** The on-disk file is `{ "payload": { …gate_feature_version, oracle_hash, entity_expert_weights, … }, "signature": { "scheme": "hmac-sha256" | "ed25519", "key_id": "<str>", "alg_version": 1, "value": "<base64>" } }`. The signature is **detached** (over `payload`, not over the whole file) — adding/rotating the envelope never perturbs the signed bytes.
- **Default scheme — HMAC-SHA256, pure-stdlib.** `sign(payload, *, key_id, key) -> envelope` uses `hmac.new(key, canonical_gate_bytes(payload), hashlib.sha256)`; `verify(envelope, *, key_set) -> dict` recomputes and compares with **`hmac.compare_digest`** (constant-time — no timing side-channel) and returns the verified payload, else raises. **No new dependency.**
- **Optional Ed25519 (asymmetric) — behind a lazy import, marked optional extra.** If a pure-Python/stdlib Ed25519 path is unavailable, the asymmetric variant requires the `cryptography` package — declared an **optional extra** (`gate-signing`), `importorskip`-gated in tests, never a hard dep, and **noted explicitly** so the dependency footprint stays honest. The HMAC path is the default and the only one exercised in-tree by default. (Rationale to record in the module docstring: HMAC needs a shared secret on both signer and verifier; Ed25519 lets the verifier hold only a public key — preferable once real key custody exists, hence Pass-2.)
- **Key identification + rotation.** The envelope carries `key_id`. `verify` takes a **key set** = `{current_key_id: key, previous_key_id: key, …}` (a `KeyRing` with a designated `current` + zero-or-more `previous` retired-but-in-grace keys). A signature whose `key_id` is **not in the ring** → loud reject. Rotation: when a key is retired it moves out of the ring (or out of the grace window) → an artifact signed with it is **rejected after grace**. The signer always signs with `current`. **Key material is Pass-2** — `AGENT_SIMULATED` uses a fixed, clearly-labelled test key (`_TEST_HMAC_KEY`, documented as NON-PRODUCTION) sourced from an env-overridable provider seam (`gate_signing_key_provider`) so real key custody (env/secret-store/HSM) drops in without code change.
- **Verify-on-load seam (the teeth).** The `moe.py` gate-loader (the S2-01 construction seam; or shipped here if S2-01 is not yet landed) accepts a gate **only** through `load_verified_gate(path, *, key_ring, verify_on_load=True)`, which reads the file, calls `verify`, and returns the payload — or raises. `MoERouter` never ingests a raw gate dict from disk on a path that bypasses verification. A `verify_on_load=False` escape hatch exists **only** for explicit offline tooling and is **never** the default and **never** reachable from the production orchestrator path (a test pins that the production seam passes `verify_on_load=True`).
- **Strictly additive / no public-API regression.** The no-gate path (`MoERouter` with no learned gate → static softmax) is **unchanged**: same constructor signature, same `route()`/`route_all()` behaviour, same NFR-026 fallback. The 631-line `moe.py` keeps every existing symbol; the only edit is an additive loader seam + optional param.

## 3. Given / When / Then (acceptance — concrete, testable)
- **A1 — round-trip valid signature loads `[UNIT-TEST]` `[SECURITY-TEST]`.** **Given** a gate payload signed by `sign(payload, key_id="k1", key=TEST_KEY)` and a key ring `{"k1": TEST_KEY}`, **when** `verify(envelope, key_set=ring)` runs, **then** it returns the exact payload (deep-equal) and raises nothing.
- **A2 — tamper a byte → verification raises (the headline) `[SECURITY-TEST]`.** **Given** a validly-signed envelope, **when** any single field of `payload` is mutated (e.g. flip one `entity_expert_weights` value, change `gate_feature_version`, or alter `oracle_hash`) **without** re-signing, **then** `verify` raises `GateSignatureError` (message names "signature mismatch") — **never** returns a payload. **Property test** (`@given` arbitrary single-field mutations over a synthetic payload): EVERY mutation that changes `canonical_gate_bytes` → raises; a mutation only to the *signature envelope's non-signed fields* that does not change the signed bytes (e.g. adding an unrelated top-level sibling key outside `payload`) is irrelevant to payload integrity but a **truncated/edited `signature.value`** → raises.
- **A3 — missing / empty / malformed signature → raises (never silent-accept) `[SECURITY-TEST]` `[CONTRACT-TEST]`.** **Given** an envelope with `signature` absent, `signature.value == ""`, `signature` not a dict, or `payload` absent, **when** `verify` runs, **then** it raises `GateSignatureError` — there is **no** code path that returns the unsigned `payload`. (Regression test documents: a bare `{...gate fields...}` legacy file with no envelope is rejected, not trust-on-first-use accepted.)
- **A4 — unknown key id → raises `[SECURITY-TEST]`.** **Given** an envelope with `key_id="attacker-key"` and a ring that does not contain it, **then** `verify` raises `GateSignatureError` (message names "unknown key id") — even if the attacker computed a valid HMAC under their own key (the ring is the trust root, not the file).
- **A5 — key rotation: old-signed artifact rejected after grace `[SECURITY-TEST]` `[AUDIT]`.** **Given** an artifact signed with `key_id="k0"`, **when** the ring is `{"current": "k1", "previous": {"k0"}}` (grace window open) → `verify` **accepts** (rotation continuity); **when** `k0` is then retired out of the ring → `verify` **rejects** with `GateSignatureError` naming the retired key. A companion test pins that the signer **always** signs with `current` (`k1`), never a previous key.
- **A6 — canonical serialization is order/whitespace invariant + value sensitive `[PROPERTY-TEST]` `[UNIT-TEST]` (NFR-005/AX-002).** **Given** two dicts equal as mappings but with different key insertion order, **then** `canonical_gate_bytes` is byte-identical and the same signature verifies both; **given** any value change, the bytes differ and the old signature fails. Replay determinism: signing the same payload N=5 times yields the identical `signature.value`.
- **A7 — verify-on-load seam fails closed `[SECURITY-TEST]` `[INTEGRATION-TEST]`.** **Given** a tampered `gate_v1.json` on disk, **when** `load_verified_gate(path, key_ring=ring)` runs (the seam the orchestrator uses), **then** it raises `GateSignatureError` and **no** gate payload is returned to `MoERouter`; **given** a valid file, the verified payload is returned. A test pins that the production construction seam calls the loader with `verify_on_load=True` (the escape hatch is not the default).
- **A8 — absence is graceful, tampering is not (NFR-026 boundary) `[CONTRACT-TEST]`.** **Given** **no** `gate_v1.json` at the path, **then** the loader returns `None` (→ `MoERouter` uses the static `entity_strengths` softmax, NFR-026) with no error; **given** a present-but-unverifiable file, the loader **raises** (does not degrade to the static fallback — present-and-broken ≠ absent).
- **A9 — constant-time comparison + no secret leakage `[SECURITY-TEST]` `[AUDIT]`.** A test asserts the verifier uses `hmac.compare_digest` (constant-time), and that `GateSignatureError` messages **never** include the key bytes, the HMAC of the correct value, or any secret material (only the offending `key_id`/`scheme`/a generic reason) — so a verification failure is not an oracle.

## 5. Notes / non-goals
- **Producer ownership boundary.** S2-02 (DistilledTopKGate trainer) **emits** `gate_v1.json`; this story supplies the **signer** S2-02 calls and owns the **verifier** on the consume path. This story does **not** build the distillation trainer, the gate's feature engineering, or the early-exit logic (DC-02 / S2-02 / S2-03).
- **No real key material.** Real signing-key custody (env var, secret store, HSM, KMS) is **Pass-2**. AGENT_SIMULATED uses a fixed, clearly NON-PRODUCTION test key behind an injectable provider seam. The story must NOT commit any real secret; the test key is an obvious dummy and is documented as such.
- **Optional asymmetric dep is honest.** The Ed25519 variant is an **optional extra** (`gate-signing` via `cryptography`), `importorskip`-gated, never imported on the default HMAC path, and called out so the dependency footprint stays truthful. Do **not** add a heavy crypto dep to the hard requirements.
- **Threat model recorded.** The signed bytes cover the gate *payload* (weights/oracle-hash/feature-version), not the filename or filesystem ACLs. The control is integrity + authenticity of the artifact content under the key ring; it is **not** confidentiality (the gate is not secret) and **not** a replacement for filesystem permissions.
- **Recall-floor is unaffected.** The S1 `SharedLayerProjector` floor still wraps fusion regardless of gate validity — this story hardens an **advisory** input; it does not change the AX-003 by-construction floor.
- **No public-API regression.** The no-gate static-softmax path keeps identical behaviour and signatures; this is additive.
