## 1. Intent
The MoE-router's gate is the heart of DC-02, but its current surface can't express a learned decision: `route()` sees only a bare `entity_type` string, so it can't condition on language, field, whether the shared-layer span was checksum/keyword-gated, or any distilled feature; and the only registration seam (`register_fusion_strategy`) has a **frozen** factory signature `Callable[[dict,int],FusionStrategy]` that can't carry a gate path / key-ring / feature config. The design's D5 seam-correction calls both out as SME API-MAJORs.

This story ships the **seam only** — the place a learned gate plugs in — with **zero routing-behaviour change**, so the risky ML body (S2-02) lands against a stable, tested, backward-compatible interface. Three additive pieces: (1) a `RouteContext` + a context-aware `route()` that threads an **advisory** `RoutingGate` (default absent ⇒ the static `entity_strengths` softmax, NFR-026); (2) a **v2 construction seam** carrying richer config the frozen v1 factory can't, with v1 left byte-identical; (3) a **single-source-of-truth + drift guard** closing the "two places a mode must be registered" hazard. The discipline is the same as the S1 floor work: additive, inert, pinned by a no-regression property test.

## 2. Approach / scope
- **`RouteContext` (new, frozen).** A `@dataclass(frozen=True)` carrying the feature-conditioned routing signal beyond `entity_type`: `language: str | None = None`, `field_path: str | None = None`, `checksum_gated: bool | None = None` (was the shared-layer span checksum/keyword-gated — the S2-03 early-exit signal), and an extensible `features: tuple[tuple[str, float], ...] = ()` (a hashable, order-stable feature vector the distilled gate reads; tuple-of-pairs not a dict so the context is hashable for cache keying + immutable for determinism). It deliberately does NOT include `entity_type` (that stays the positional arg, so existing call sites are untouched and the context is purely additive features).
- **Widen `MoERouter.route()` (additive, inert).** New signature `route(self, entity_type: str, *, context: RouteContext | None = None) -> list[tuple[str, float]]`. When `context is None` (every existing caller — `route_all()` `moe.py:381`, `MoEFusionStrategy.merge()` `moe.py:489`) the path is **byte-identical** to today: same static-softmax computation, same cache. The cache widens from `dict[str, …]` keyed on `entity_type` to keyed on `(entity_type, context)` (a frozen `RouteContext` is hashable; `None` is a distinct key) so two different contexts for the same entity type don't collide — the `None` key reproduces the current cache exactly.
- **`RoutingGate` Protocol (new, advisory).** A `@runtime_checkable typing.Protocol` mirroring the S3-01 `RatingEnginePort` pattern: `adjust(self, entity_type: str, context: RouteContext | None, base: list[tuple[str, float]]) -> list[tuple[str, float]]` — given the static-softmax `base` weights, return advisory re-weighted/re-ordered `(expert_id, weight)` pairs. `MoERouter.__init__` gains `gate: RoutingGate | None = None`; `route()` computes the static `base` exactly as today, then **iff `gate is not None`** calls `gate.adjust(...)` and uses its result (re-normalized + validated). **Default `gate=None` ⇒ `route()` returns `base` unchanged.** The gate is **advisory on weighting/selection only** — it can re-order or re-weight experts but the **recall-floor no-drop invariant is enforced downstream by the `FloorProjectingFusion`/`SharedLayerProjector`** (FR-016/AX-003, untouched): a gate can never cause a shared-layer span to be dropped because the floor re-injects it post-fusion. This story does NOT ship a `RoutingGate` implementation — only the Protocol + the plug (S2-02 ships `DistilledTopKGate`).
- **v2 fusion-construction seam (new, additive; v1 frozen-untouched).** `register_fusion_strategy` + `CustomFusionFactory = Callable[[dict[str,float], int], FusionStrategy]` (`fusion.py:405/409`) stay **byte-identical** (a real public API — `available_fusion_modes()` discovers them; do not change). Add alongside: a `FusionBuildSpec` frozen dataclass `{mode, weights, min_consensus, entity_weights, iou_threshold, gate_path, key_ring, top_k}` (carries everything `build_fusion` + a feature-conditioned MoE need, incl. the S2-05 gate path/key-ring), `CustomFusionFactoryV2 = Callable[[FusionBuildSpec], FusionStrategy]`, a `_CUSTOM_FACTORIES_V2: dict[str, CustomFusionFactoryV2]` registry, and `register_fusion_strategy_v2(mode, factory)`. `build_fusion` consults `_CUSTOM_FACTORIES_V2` **additively** (after the builtin dispatch, before/around the existing `_CUSTOM_FACTORIES` v1 fall-through), passing a `FusionBuildSpec` it assembles from its kwargs. This is the path S2-02 registers the gate-configured MoE mode through.
- **Single-source-of-truth + drift guard (the "BOTH places" SME MAJOR).** Today `available_fusion_modes()` hardcodes a `builtin` list (`fusion.py:445-451`) that can silently drift from `build_fusion`'s `if mode == …` dispatch (`fusion.py:490-520`). Extract `_BUILTIN_FUSION_MODES: tuple[str, ...]` as the single constant `available_fusion_modes()` reads (additive refactor; same returned list). Add a **drift-guard test** (`[AUDIT]`): every mode in `available_fusion_modes()` is **constructible** by `build_fusion(mode, …)` without `FusionError` (round-trip), and every builtin `if mode ==` branch in `build_fusion` is advertised by `available_fusion_modes()` — so a new mode added to one place but not the other fails CI. The guard is non-vacuous (a meta-check proves an unadvertised/unconstructable mode is caught).
- **No-regression teeth (the load-bearing safety net).** A property test pins that for a representative set of entity types, `MoERouter(...).route(et)` (no context, no gate) is **identical** before/after this change (same experts, same weights, sum-to-1.0), and `build_fusion(mode, …)` returns the same strategy type for every existing builtin mode. The widening is provably inert on every existing path.

## 2a. Pre-claim de-risk (verified against live code 2026-06-03)
- **RISK-1 (`register_fusion_strategy` is public API):** `register_fusion_strategy` + `CustomFusionFactory` + `available_fusion_modes()` are exported and user-facing (custom fusion modes selectable via `ProcessingProfileSpec.mode`). Do **NOT** change the v1 factory signature or `register_fusion_strategy`'s behaviour — add the **v2** seam alongside. md5-diff `fusion.py` for the v1 symbols (signature lines unchanged).
- **RISK-2 (two `route()` call sites must stay green):** `route()` is called at `moe.py:381` (`route_all`) and `moe.py:489` (`MoEFusionStrategy.merge`), both with a **bare `entity_type`** and no context. The widening MUST be keyword-only-additive (`*, context=None`) so these are untouched; the no-regression test pins both behaviours.
- **RISK-3 (recall-floor invariant is NOT this story's to weaken):** the gate is **advisory**; the `FloorProjectingFusion` + `SharedLayerProjector` (S1-01/02, `routing/floor_fusion.py`, `routing/shared_layer.py`) own the no-drop floor (FR-016/AX-003) and are **byte-identical** here. An acceptance test asserts that even a hostile gate (one that zeroes an expert's weight) cannot defeat the floor (the floor re-injects post-fusion) — i.e. the gate's advisory scope is structurally bounded.
- **RISK-4 (determinism / cache):** the `RouteContext` is frozen + hashable; the widened cache key `(entity_type, context)` is deterministic; gate `adjust()` output is re-normalized + validated (finite, in-range, sums to 1.0) so a misbehaving gate can't emit NaN/negative weights. Two `route()` calls on the same `(entity_type, context)` return equal results (AX-002 / NFR-005).
- **RISK-5 (no behaviour change ships):** this is a **seam-only** story. The `RoutingGate` Protocol has **no in-tree implementation** that alters routing (the default `gate=None` no-op is the only path exercised on the production fusion build). The S2-02 `DistilledTopKGate` is the first real gate. The no-regression test is the proof.
- **RISK-6 (user-WIP / off-limits):** `orchestrator.py` is user-WIP (NOT touched — S2-03's early-exit wire-in is separately deferred); `tests/test_moe_enhancements.py` is user-WIP (NOT touched — new tests go in new files `test_moe_router_seam.py` + `test_fusion_construction_seam.py`); `evaluation/competitor_compare.py` byte-identical (RISK-6, md5 `7cae16c89f4c97136e1a12394dae2025`); `artifacts/benchmarks/*` never written.
- **AX-001 (synthetic fixtures):** all test experts/spans use synthetic data (`"PERSON_NAME"`, `"jane.roe@example.test"`); no real PII.
- **Import isolation:** the new symbols live in `moe.py`/`fusion.py` (the swarm pillar — already free to import each other lazily); they import **nothing** from `eval_framework.rating`/`attacks`/the SDO gate (the eval import-boundary is one-directional and unaffected).

## 3. Given / When / Then (acceptance — concrete, testable)
- **A1 — `route()` widened, context-aware, backward-compatible `[CONTRACT-TEST]`.** **Given** a `MoERouter` over a synthetic registry, **when** `route("PERSON_NAME")` is called with no `context` and no `gate`, **then** the result is byte-identical to the pre-story static-softmax output (same experts, same weights, Σ=1.0); **and** `route("PERSON_NAME", context=RouteContext(language="es"))` is accepted (no TypeError) and — with no gate — returns the same static base (context is inert without a gate).
- **A2 — no-regression on all existing call sites `[PROPERTY-TEST]`.** **Given** a representative set of entity types over the default registry, **when** `route_all()` and `MoEFusionStrategy.merge(findings)` run, **then** every routed weight set is identical to the pre-story baseline (a recorded/recomputed reference) — proving the two bare-`entity_type` call sites are untouched.
- **A3 — `RoutingGate` Protocol + advisory plug `[UNIT-TEST]`.** **Given** a synthetic in-test `RoutingGate` that re-weights (e.g. boosts one expert), **when** a `MoERouter(..., gate=that_gate)` routes, **then** `gate.adjust(entity_type, context, base)` is called with the static base and its (validated, re-normalized) output is returned; **and** `isinstance(that_gate, RoutingGate)` is True (`@runtime_checkable`); **and** with `gate=None` the gate is never consulted (base returned unchanged).
- **A4 — advisory scope is bounded: a gate cannot defeat the floor `[CONTRACT-TEST]` `[AUDIT]`.** **Given** a hostile gate that zeroes the shared-layer (regex-oss) expert's weight, **when** the full `FloorProjectingFusion(MoEFusionStrategy(... gate=hostile ...))` pipeline runs on a doc with a checksum-gated shared span, **then** the shared span is STILL present in the output (the floor re-injects it post-fusion, `provenance=shared_floor`) — the gate's advisory re-weighting cannot drop a floored entity (FR-016/AX-003 preserved).
- **A5 — gate-output validation (determinism / safety) `[UNIT-TEST]`.** **Given** a misbehaving gate returning non-finite / negative / non-normalized weights, **when** `route()` post-processes its output, **then** the result is re-normalized to a valid distribution (finite, ≥0, Σ=1.0) OR falls back to the static base with an audit note — never propagates NaN/negative weights downstream.
- **A6 — v2 construction seam, v1 untouched `[CONTRACT-TEST]`.** **Given** `register_fusion_strategy_v2("feature_moe", factory_v2)` where `factory_v2(spec: FusionBuildSpec) -> FusionStrategy`, **when** `build_fusion("feature_moe", weights=…, min_consensus=…, …)` is called, **then** the v2 factory is invoked with a populated `FusionBuildSpec` (carrying `gate_path`/`key_ring`/`top_k`/etc.) and its strategy is returned; **and** the v1 `register_fusion_strategy` + `CustomFusionFactory` signature + an existing v1-registered mode are **unchanged** (byte-identical symbols; a v1 mode still constructs).
- **A7 — `available_fusion_modes()`/`build_fusion()` drift guard `[AUDIT]`.** **Given** the single-source `_BUILTIN_FUSION_MODES`, **then** every mode `available_fusion_modes()` advertises is constructible by `build_fusion(mode, …)` without `FusionError`, and every builtin `build_fusion` branch is advertised; a non-vacuous meta-check proves a mode added to only one place is caught. (Closes the "register the new mode in BOTH places" SME MAJOR with teeth.)
- **A8 — NFR-026 graceful-degradation default `[UNIT-TEST]`.** **Given** no gate artifact and no `gate=`, **then** the router runs entirely on the static `entity_strengths` softmax with 0 unhandled exceptions and no silent recall loss (the structural default) — and constructing `MoERouter(gate_path=missing_path, key_ring=kr)` (absent file) keeps `gate_payload=None` and the static path (S2-05 behaviour, re-confirmed).
- **A9 — determinism `[PROPERTY-TEST]`.** **Given** the same `(entity_type, context)` (and a fixed gate or none), **when** `route()` is called twice, **then** the two results are equal (AX-002 / NFR-005); the `RouteContext` is frozen+hashable (a mutation attempt raises).
